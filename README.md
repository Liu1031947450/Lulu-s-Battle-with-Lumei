# 噜噜大战噜妹

**一场软乎乎的对决。** 完整中文双人 / 人机格斗游戏：二维战斗场景中使用真实 3D 角色，包含 16 种动画状态、五种背景地图、轻快音效与命中特效。

## 直接开玩

打开本目录的 **`index.html`**，选择「人机对战」或「双人对战」，三秒后开打。

- 不需要安装任何软件依赖，不需要服务器、不需要导入素材，也不需要联网。
- 可以只复制 `index.html` 到另一个文件夹或电脑，它仍然包含完整游戏。
- ZIP 交付包请先解压，再打开其中的 `index.html`。
- 推荐桌面浏览器与键盘。移动端支持页面布局，但这版不是触屏格斗游戏。
- 背景音乐在第一次点击模式按钮后启动；右上角可以静音。浏览器不允许页面未经点击自动发声。
- 右上角「设置」可选择人机难度：**简单 / 中等 / 困难 / 地狱模式**，默认中等，保留原有表现。选择自动保存在当前浏览器；存储不可用时仍可在本页使用。
- 难度只影响电脑的反应与攻防决策，不增加血量、伤害或缩短技能冷却，也不影响双人模式。对局中打开设置会暂停，关闭后继续；更改从**下一局或重开后**生效。
- 角色优先使用 WebGL 2 渲染；硬件加速不可用时保留原二维角色与全部玩法。三视图及动作预览可直接打开 `assets/models/preview.html`。
- 首页保留橘子云朵花园；开始或重开对局时随机切换花园、落日海滨、樱花庭院、极光雪原、霓虹天台，避免连续重复。对局内地图固定，地面、边界、角色与战斗规则不变。
- 开局播放可爱弹跳数字与中文女声“三、二、一、开始！”，仍为三秒准备；语音已内嵌，离线可用。暂停会冻结演出并停止播报，恢复不重复报数；静音开关同时控制语音。

## 操作教程

| 动作 | 玩家 1：噜噜 | 玩家 2：噜妹 |
| --- | --- | --- |
| 左 / 右移动 | A / D | ← / → |
| 地面奔跑 | 快速双击 A 或 D，并按住 | 快速双击 ← 或 →，并按住 |
| 跳跃 / 二段跳 | W；松开后再按一次 | ↑；松开后再按一次 |
| 下蹲 / 起身 | 按住 S / 松开 S | 按住 ↓ / 松开 ↓ |
| 普通攻击 | J | 小键盘 1 |
| 专属技能 | K | 小键盘 2 |
| 地面防御 | 按住 L | 按住小键盘 3 |
| 暂停 / 继续 | Esc | Esc |
| 重新开始 | R，或点击「重新开始」 | 同左 |

没有小键盘时，噜妹也支持**主键盘上方的 1 / 2 / 3**，不会占用噜噜的按键。小键盘按物理键位识别，Num Lock 开关不改变技能映射。

### 第一局可以这样玩

1. 选择「人机对战」，你操控噜噜，噜妹由电脑操控。
2. 用 A / D 接近噜妹，按 J 轻轻出拳；太远或高度不对时不会命中。
3. 对手准备出招时按住 L 防御，再抓住她收招的空隙反击。
4. 橘子图标的冷却条满时按 K，发动「橘子冲冲」。
5. W 可以跳跃；在空中松开再按一次 W 可以二段跳、跳过对手。落地后恢复两次跳跃机会。
6. 双人模式由另一位玩家使用方向键和 1 / 2 / 3，与噜噜同屏对战。

## 对局规则

- 双方初始生命 100，每局 90 秒；准备倒计时不计入对战时间。
- 普攻伤害 8。噜噜「橘子冲冲」为短距离突进，伤害 18；噜妹「爱心泡泡」为飞行投射物，伤害 16。两种技能均冷却 3 秒。
- 攻击有前摇、有效窗口和后摇；同一次攻击对同一目标只结算一次。普攻和技能需要重新按键，不会因系统键盘重复事件自动连发。
- 地面正面防御减伤 80%，但仍有少量伤害和轻微击退；背后攻击与空中不能格挡。出招和受击时不能立即抢先防御。
- 受击包含击退、硬直及短暂恢复保护，不能一直把对手锁在硬直里。
- 生命归零判负；双方同帧归零为平局。时间用尽比较剩余生命，相同则平局。
- 胜负结束后可再次挑战或返回主页。重开会清除生命、冷却、投射物、特效、按键和战斗统计。
- 切换窗口或页面进入后台时自动暂停，返回后点击继续，不会自动追算离开期间的伤害。

## 项目内容

```text

src/
  engine.js                    固定 60Hz 战斗逻辑与四档难度人机
  input.js                     双人键盘输入、双击奔跑、按键边沿
  art.js                       统一角色入口、姿势、场景、特效及二维回退
  characters.mjs               内嵌 GLB 加载、实时 3D 渲染与画布合成
  character-rig.mjs            共享头部 / 四肢 / 表情关节映射
  model-preview.html           三视图与动作预览源模板
  audio.js                     原创旋律与音效合成器
  app.js                       界面、暂停、音效、渲染循环
  page.html / style.css        页面源模板与样式
assets/
  models/                      两个带 16 动作的 GLB、三视图、离线预览和导入示例；SVG 为二维回退
  sprites/                     全动作 PNG 图集与逐帧 JSON 坐标
  portraits/                   两个透明背景角色立绘
  backgrounds/                 2560×1240 花园背景
  effects/                     特效图集与坐标
  audio/                       原创花园旋律、各类音效与四段中文开场语音 WAV
  animation-definitions.json   16 种动画的帧数、速率和循环定义

tests/                         Node 核心测试和离线浏览器完整流程测试

VALIDATION.md                  本次实际验收结果与边界
```

角色 GLB 与逐帧图集来自同一套三维网格，**不是将静态立绘平移充当动画**。实时动作包括身体形变、头部跟随、四肢关节、眨眼、口型、二段跳旋转、格挡护盾、受击与胜负姿态。成品内嵌 Three.js 和两份 GLB，不依赖读取旁边的模型或图片文件。模型路径、坐标约定、动画播放代码和再生成方法见 `assets/models/README.md`。

## 开发与再构建（仅供维护，不是游玩步骤）

开发需要 Node.js 22 或以上；安装开发依赖后可重建模型 / 页面并运行核心与 GLB 测试（游玩不需要安装）：

```sh
npm ci
npm run build
npm test
```

四段开场 WAV 已随源码提供，普通构建不依赖系统语音。仅重新制作语音时，在带有 Tingting 中文音色的 macOS 上运行 `npm run voices`，再运行 `npm run build`；语音来源及参数见 `ASSETS.md`。

浏览器验收与高分辨率资源导出使用开发依赖 Playwright，不进入游戏运行时：

```sh
npm ci
npx playwright install chromium
npm run test:browser
npm run assets
npm run package
```

macOS 上若已有 Google Chrome，脚本默认使用系统 Chrome。也可设置 `BROWSER_CHANNEL`，或者安装对应测试浏览器后通过 `TEST_BROWSER=firefox` / `TEST_BROWSER=webkit` 执行浏览器测试。

`npm run check` 重新构建并运行核心与 Chromium 流程验收。`npm run package` 使用系统 `zip`，将成品、源码、资源、说明和验收证据打成压缩包；不会打包 `node_modules`。

战斗逻辑不依赖 DOM，键盘与人机走相同的输入接口。测试中可以用固定种子复现人机对局；发布页面只暴露只读 `LuluGame.snapshot()` 诊断，不提供改血量的作弊入口。

## 常见问题

- **看见代码而不是游戏：** 用浏览器打开 `index.html`，不是文本编辑器，也不是源模板 `src/page.html`。
- **没有声音：** 先点击一次对战模式，检查右上角声音按钮和设备音量。即使音频被浏览器限制，战斗仍然正常运行。
- **W / J 等键没反应：** 确保页面处于前台且没有暂停弹窗；在使用输入法的系统上切到英文键盘输入状态。
- **小键盘键位不方便：** 直接使用主键区 1 / 2 / 3。部分键盘同时按很多键会有硬件冲突，网页不能突破键盘本身的按键扫描限制。
- **窗口较小：** 首页与对战按可用宽高等比缩放场地，短屏压缩留白、收起次要文案，尽量一屏展示；血条和倒计时随实际场地大小适配，战斗坐标和伤害不变。过矮屏幕的帮助 / 设置弹窗保留内部滚动，避免裁掉按钮。
- **对局被暂停：** 离开窗口会自动暂停，这是防止回来发现角色已被击败的保护行为。
